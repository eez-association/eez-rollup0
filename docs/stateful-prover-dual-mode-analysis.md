# Stateful Prover — Dual-Mode Architecture Analysis

*Audience: eez-rollup0 core team. Status: design analysis, no code shipped. Every file:line below was read this session unless explicitly attributed to a prior verification pass.*

> **Model revision (this pass).** The original document designed the stateful backend as a self-contained durable node: a full GB-scale trie, a `(height, block_hash)` fact archive, its **own** parent-hash reorg detector, and its **own** durable rollback engine — all because "the prover has no L1 view." We now adopt a sharper model that **collapses most of that machinery** and fixes a soundness gap the old framing left open:
>
> - **(M1) Durable state only to the L1-FINALIZED frontier; optimistic blocks live in an IN-MEMORY speculative overlay.** Above the L1-finalized boundary, blocks live in reth's in-memory tree. The dominant reorg in this system — the optimistic-bundle rollback (`recover_failed_batch → committer.reorg_to`) — only touches that in-memory overlay and is rebuilt by re-execution, with **NO durable rollback**. This **removes the custom `(height, block_hash)` archive + parent-hash detector + durable rollback engine** the old §5/§7 specified.
> - **(M2) Finality-driven persistence.** The durable boundary is driven by L1-confirmed/finalized height (reth forkchoice `safe`/`finalized`); unfinalized blocks stay reorg-able in the in-memory tree. (Correction below: reth's *physical* persistence is distance-from-head, not finality-driven, so M2 is a config/wiring requirement, not a free property.)
> - **(M3) The prover has its OWN INDEPENDENT L1 connection** — not the composer's embedded L1. This is required for **soundness**, not robustness: once M1 lets the prover stop re-executing below a "confirmed" frontier, that frontier becomes a trust root, and a frontier sourced from the entity being verified is not verification. M3 reuses the deriver's already-factored L1-follower machinery (the reth-free `eez-l1` crate) against the prover's own L1 node. **The original doc claim "the prover has no L1 view" is superseded — it now gets one, by design.**
>
> - **(This revision) Gap-report integration.** This version folds in an adversarial gap-hunt (**G1–G9**) and two design-discussion refinements: the **copy-A / copy-B** framing of what each backend *executes* vs *reads*, and the **frontier-is-irreducibly-composer-sourced** point (the DA is **circular** — a block is not published anywhere until the proof signs it, so the prover's independence is **re-computation**, not an independent data source). The headline result: **G1 is the one true soundness blocker.** Under the stateful backend the settlement/cross-chain gates read the composer's *re-supplied* `event.block` bytes, which are **not** preimage-bound to what the follower executed, so a forged `event.block` can produce a fully-correct `VerifiedWindow` with **no self-reject** (outbound-A3 escrow **forgery**, not a liveness gap). Its tx-only gate-input bind must land before any stateful code; the full structural copy-A routing must be in place before any stateful output is trusted/signed/settled (§8.G1, §11 Phase 1 binding / Phase 3 full). Accordingly the §8 "a divergent backend self-rejects via its own gates" guarantee is **corrected** to hold **only for state-root-captured facts**. The remaining gaps are sequenced into the plan: G4 is a Phase-2 (M3) blocker, G2/G3 a Phase-3 honesty-correction + sync/async decision, G5/G6/G7 Phase-4 follower-bound realities, G8/G9 future-zkVM-phase roadmap items (§11, §12).

## 1. Executive summary + recommendation

eez-proverd today is **stateless**: for each `VerifyRange[from..to]` directive it re-executes the *entire* window from an anchor using execution **witnesses** (ZisK `native-validate`), recomputes every per-block root and the `publicInputsHash`, runs the settlement gates, hard-cross-checks the recomputed hash against the on-wire `postBatch` calldata, and ECDSA-signs an attestation. The witness-sourcing subsystem that feeds this (eez-node's witness task, O(distance) backfill, the bounded control-feed ring) is the operational fragility this proposal targets, together with the cost of re-executing the whole settled-to-tip backlog on every directive.

The proposal: add a **stateful** prover backend that holds the L2 state and advances it incrementally, so it needs **no witnesses** for already-consolidated history and does **not** re-execute the whole window each directive. The system must keep both modes and stay byte-compatible with the composer, the wire, the public inputs, the settlement gates, and the on-chain verification.

**The structural claim is sound; the new model makes the operational design tractable where the old one was not.** I confirmed the abstraction boundary is real, narrow, and single-sited: `validate_window → VerifiedWindow` is the *only* witness consumer (`crates/eez-proverd/src/main.rs:647`, witness required at `main.rs:667`, subprocess at `main.rs:677-683`), it has exactly one call site (`main.rs:2071`), and the on-chain contract verifies *only* `ecrecover(publicInputsHash, proof) == signer` (`sync-rollups-protocol/src/proofSystems/ECDSAProofSystem.sol:30-31`) over a hash rebuilt from calldata alone (`sync-rollups-protocol/src/EEZ.sol:634/636`), never validating `newState` (`EEZ.sol:1006` only telescopes `config.stateRoot == delta.currentState`). So at the **signature layer** a stateful and a stateless attestation are literally indistinguishable on-chain.

**What the new model changes versus the original design:**

- **M1 deletes the hardest piece of the old plan.** The old §5/§7 built a custom durable rollback engine + `(height, block_hash)` archive + feed-native parent-hash detector specifically to survive the dominant optimistic-bundle reorg in durable state. Under M1 that reorg never reaches durable state: everything above the L1-finalized boundary is reth's in-memory tree, and an optimistic reorg is just an in-memory re-execution. The dominant reorg becomes a non-event for the durable store. The residual hard case shrinks to **one rare class** — a finality reversion / too-deep L1 reorg (§7).
- **M3 closes a soundness gap the old model left implicit.** The directive's `from` is `settled + 1` (`composer.rs:411`, where `posted = rollup.l1_head.cursor()` at `composer.rs:390`), i.e. it *lags the tip* and is **composer-asserted**. Today that is provably harmless — the prover re-executes everything and the cursor is "only a resume HINT … a wrong H cannot make a bad batch attest" (`main.rs:1707-1709`). But **M1's consolidation converts that hint into a trust root**: a prover that stops re-executing below the composer-supplied frontier can be driven to sign on an orphaned base whenever the composer's view diverges from real L1 undetected. M3 (the prover's own L1 node) is therefore a **hard prerequisite that must land with or before M1**, not defense-in-depth.
- **The fact production is still not "free reuse."** `Deriver::execute_block` returns only `(ExecutionData, SealedHeader)` and discards the `outcome` carrying receipts (`deriver.rs:424`, return at `deriver.rs:558-561`). It produces neither `sync_per_tx_roots` nor `sync_tx_statuses`. Omitting `sync_tx_statuses` makes `system_txs_succeeded(None) → true` with only a warning (`main.rs:914-917`) — a **fail-OPEN** that silently disables the reverted-system-tx (#10) gate. The per-tx root path must additionally replicate native-validate's no-op soundness guard byte-for-byte (`/home/ubuntu/zisk-patch-stateless/crates/stateless/src/validation.rs:409-419`). **This crux is unchanged by the new model** and still governs §8.

**Recommendation.**
1. Ship **Phase 0 (trait extraction)** and **Phase 1 (close the soundness holes — the G1 gate-input bind + the S2 hard-fail)** now: stateless-safe (both are no-ops on today's stateless path), fully revertible, and the precondition for trusting anything stateful. The *standing* shadow-check moves to **Phase 3** (the observer), where the stateful backend it must compare actually exists.
2. **Stand up the prover's own independent L1 follower (M3) as the gating dependency for any consolidation.** Instantiate `eez-l1`'s `L1Watcher` + read-only `Submitter` + `L1CanonicalHead` in the prover against its **own** `EEZ_L1_RPC_URL` (a separate node), reusing the deriver's subscribe→resync→audit loop. This is mostly wiring — the machinery already exists and is reth-free.
3. Build the stateful backend as a **finality-pinned follower**: durable reth state only up to the prover's own L1-**finalized** boundary, an **in-memory overlay** above it, serving a directive's body from held/overlay state and **re-executing only the single Sync block `to`** on demand with per-tx instrumentation. **No custom durable rollback engine** — optimistic reorgs are in-memory re-execution; only a finality reversion can move the durable base.
4. Keep statelessness as the always-correct oracle and the **guaranteed fallback floor** for: cold boot, own-L1 lag past the cap, `ReorgTooDeep`/watcher halt, and any persistent own-L1 disagreement. Run **hybrid only**; do not offer a pure-stateful daemon. Consolidation is a **strict optimization**, never a precondition for producing a sound attestation.
5. Treat the real stateful zkVM as a separate, multi-quarter track behind the *same* on-chain seam (a second registered `IProofSystem`), decided independently. M3's own L1 is also the precondition for ever enabling **bound** settlement / anti-replay (§9, §10).

**Honest bottom line:** the on-chain indistinguishability is real and the change is genuinely additive at the trait seam. Under the new model the stateful backend is an **embedded finality-pinned follower** (reth in-memory tree + committer + an own L1 follower + a durable datadir bounded at finality), and its hardest problems are now (0) the **G1 soundness blocker** — the settlement/cross-chain gates read the composer's re-supplied `event.block` (copy B), which is **not** preimage-bound under the stateful backend, whose tx-only gate-input bind must land before any stateful code and whose full structural copy-A reroute must be in place before any stateful output is trusted/signed/settled (§8.G1) — (a) **STF bit-parity against a *different* reth/revm build, continuously** (unchanged), and (b) the **one residual durable-rollback case** — a finality reversion / too-deep L1 reorg — which the live `eez-l1` code currently *mishandles* (it swallows `ReorgTooDeep` and retries, `l1_watcher.rs:276-285`, instead of halting). The dominant optimistic reorg, which dominated the old design, is no longer a durable-state problem at all.

## 2. Current stateless architecture recap

**The seam.** `VerifiedWindow` is a 5-field, witness-agnostic struct (`main.rs:624-641`):

```
parent_state_root: B256
final_state_root:  B256
per_block_roots:        Option<Vec<B256>>   // every block's PROVEN post-state root
sync_per_tx_roots:      Option<Vec<B256>>   // the Sync (last) block's per-tx pair_roots
sync_tx_statuses:       Option<Vec<bool>>   // the Sync block's per-tx receipt statuses
```

`validate_window(window, validator_bin, chain_config, work_dir) -> eyre::Result<VerifiedWindow>` (`main.rs:647`) is the **only** function that touches witnesses: it requires every event to carry one (`main.rs:667`, bails otherwise), stages `block-{n}.rlp` + `witness-{n}.json` per event (`main.rs:670-672`), shells out to `native-validate <chain_config> --dir <dir>` (`main.rs:677-683`), and asserts each validated block hash equals the composer-claimed `event.block_hash` (`main.rs:726-735`). It parses `per_block_roots`, `pair_roots` (→ `sync_per_tx_roots`) and `tx_statuses` (→ `sync_tx_statuses`) from the last block's JSON summary (`main.rs:766-777`) and returns the struct (`main.rs:798-803`).

**The single call site** is `main.rs:2071`: `if let (Some(vbin), Some(cfg)) = (&args.validator_bin, &args.chain_config)` → `validate_window(...)` → `verified = Some(vw)` on success, `window_ok = false` on error, with an `else` observer branch (`main.rs:2080-2085`). Note `validate_window` is invoked **per max-window chunk**, not per directive.

**Everything downstream consumes only `VerifiedWindow` + batch + RLP**, never witnesses:
- Telescope fill and the cross-chunk continuity check: `batch_anchor_root` captured from chunk 1's `vw.parent_state_root` (`main.rs:2129`), each later chunk asserts `vw.parent_state_root == prev_chunk_final_root` else `window_ok = false` (`main.rs:2133-2141`).
- `verify_settlement_public_inputs` (`main.rs:820`) rebuilds `publicInputsHash` from `pb.abi_calldata` + vkey only and hard-cross-checks; it bails if `n_ps != 1` (`main.rs:828`) and if `blockNumber != 0` (`main.rs:831-836`, timeless-only).
- Settlement-chain gates: OD-5 anchor, endpoint, interior proven-root, #10 (`verify_settlement_chain`/`classify_settlement_chain` at `main.rs:1277`, the #10 check at `main.rs:1380` calling `system_txs_succeeded`).
- Inbound bijection (`multi_inbound_outcome_gate`) and outbound A3 (`verify_outbound_authorized` / `crates/eez-evm/src/outbound_gate.rs`).
- Attest + submit via ECDSA signing and `SlotProof`.

**Durable resume.** `DrivenCheckpoint` (`main.rs:185-195`) persists `proved_to` **plus telescope state** (`batch_anchor_root`, `prev_chunk_final_root`, `prev_chunk_last_hash`) per directive; it is loaded into a `DrivenResume` (`main.rs:198-203`) and gates the subscribe `from_block`. This is the *existing* durable prover cursor — any stateful design must reconcile with it (§7, §11).

**The prover has no L1 connection today (the M3 gap, confirmed).** `eez-proverd`'s `Args` (`main.rs:118-178`) expose only `EEZ_CONTROL_RPC_URL` (the composer control feed, `control_addr` at `main.rs:123`) and `EEZ_L2_RPC_URL` (an L2 archive for witness backfill, `l2_rpc_url` at `main.rs:175`). There is **no** `EEZ_L1_*` argument; `backfill_block` (`main.rs:419`) hits the L2 RPC, never L1. The container wiring confirms it (`docker-compose.driven.override.yml:54-77` — control + L2 only). The code admits the gap in words: the bound-settlement arm "folds a composer-supplied L1 blockhash with **NO independent L1 oracle** here to check it. Refuse until such an oracle exists" (`main.rs:817-818`), enforced by bailing on any `blockNumber != 0` (`main.rs:831-836`). So today the prover's entire notion of "what is settled/finalized on L1" is **100% composer-asserted** — exactly what M3 targets.

**On-chain.** `_verifyProofSystemBatch` builds `publicInputsHash = keccak256(abi.encodePacked(sharedPublicInput, acc))` (`EEZ.sol:634`) and calls `IProofSystem(...).verify(proofs[k], publicInputsHash)` (`EEZ.sol:636`); `ECDSAProofSystem.verify` returns `ECDSA.recover(publicInputsHash, proof) == signer` (`ECDSAProofSystem.sol:30-31`). `_applyStateDeltas` reverts only on `config.stateRoot != delta.currentState` (`EEZ.sol:1006`) — it never checks `newState` correctness, and stores no L2 height (per-rollup on-chain state is only `bytes32 stateRoot` + `etherBalance`, `RollupConfig` at `sync-rollups-protocol/src/interfaces/IEEZ.sol:72-75`; `rollups(rollupId)` getter at `EEZ.sol:65`). The `IProofSystem` interface is `verify(bytes,bytes32) → bool` (`IProofSystem.sol:15`).

## 3. What "stateful prover" means here, and why

**Definition (this codebase, new model).** A backend that holds the L2 state (a real reth state trie) **durably up to its own L1-finalized boundary** and keeps the optimistic span above that in reth's **in-memory tree**, advancing it block-by-block as blocks become canonical, then serving each directive's facts from that held/overlay state plus on-demand Sync-block re-execution, so that:
- it needs **no execution witnesses** for consolidated history — BLOCKHASH/EIP-2935 reads resolve from the held trie, not from a witness;
- it does **not** re-execute the settled-to-tip backlog on every directive — each block is executed once when first seen, and re-executed only when an *optimistic* reorg rebuilds the in-memory overlay.

**The three-tier state model (the heart of M1/M2).** The codebase already separates these three levels at the consensus layer via reth's forkchoice triplet (`unsafe_head_hash` / `safe_header` / `finalized_hash`, `block_committer.rs:468-472`, assembled in `forkchoice_state` at `block_committer.rs:568-574`). The stateful prover must mirror all three against its **own** L1 view (M3), not collapse them:

- **Tier A — optimistic overlay (above own `safe`).** L2 blocks above the prover's own L1-confirmed head. reth `safe` ← `L1CanonicalHead.cursor()` (`crates/eez-l1/src/l1_canonical_head.rs:43`), advanced only by a landed `BatchPosted` (`deriver.rs:759` → `advance_safe_finalized` at `deriver.rs:931`). **In-memory, rebuilt by re-execution.** The optimistic-bundle reorg lives entirely here.
- **Tier B — confirmed-but-not-finalized (between own `finalized` and own `safe`).** L1-*included* but still reorg-able up to `reorg_max_depth` (default **62**, `l1_watcher.rs:152/155`): a shallow L1 reorg rolls it back via `retreat_on_l1_reorg` (`l1_canonical_head.rs:150`, which retreats `cursor` and clamps `finalized_l2` only if it would cross). **This tier is NOT truly durable** and must stay in the overlay (re-executed), not consolidated.
- **Tier C — truly durable (at or below own `finalized`).** `finalized_l2` (`l1_canonical_head.rs:48`), mapped from the L1-finalized block via `highest_l2_at_or_below_l1` (`l1_canonical_head.rs:171`), driven by the watcher's `eth_getBlockByNumber("finalized")` poll (`l1_watcher.rs:41/617`) → reth `finalized`. Under honest L1 it **only advances**; the *only* event that moves it back is a finality reversion (§7, the residual hard case).

**The consolidation boundary is Tier C (finalized), NOT `cursor`.** The original model implicitly consolidated at "L1-confirmed = inclusion." That is wrong: inclusion (`cursor`) is reorg-able ≤62 blocks, so a durable base at inclusion would roll back on **every** shallow L1 reorg — defeating M1's "no durable rollback" promise. Binding the durable base to **finalized** makes the lag case (a) and the shallow-reorg case (b1) structurally unable to touch durable state (§7).

Two distinct things must not be conflated:
- **A stateful native-reexecution attester (near-term).** Holds reth state to the L1-finalized boundary, advances it, emits the same `VerifiedWindow`, signs the **same** ECDSA attestation. Trust model is *identical* to today (ECDSA over a calldata-derived hash) — **provided M3 makes the consolidation boundary the prover's own, not the composer's**. This is what this document designs.
- **A real stateful zkVM (future).** Produces a SNARK whose continuation carries the state commitment. Different trust model, different on-chain verifier, registered as a *second* `IProofSystem` (§10). Not built here.

**Why pursue it.**
- **Reduce witness-sourcing fragility — for the non-settling body only.** The witness task in eez-node, the O(distance-from-tip) reverse-state backfill, and the ring witness pressure all exist to feed `native-validate`. A finality-pinned follower that holds state lets the prover **skip re-execution of the non-settling body** for the stateful backend's own consolidated windows, dropping the `{state, codes, keys, headers}` dependency *there*. This is **not** a system-wide "kill witnesses" win: every settling directive still hard-bails without a witness, and the shadow never retires while any stateful output is trusted (§11/§12 G2). It also moots the recurring EIP-2935 0-header / `MissingAncestorHeader` witness race (memory records this as a live divergence landmine) on that path — there is no by-hash ancestor-header resolution at all.
- **Cheaper steady state — only in the post-shadow regime.** The stateless path re-executes `[settled+1 .. tip]` *every slot* (the backlog body is repeated work); the follower executes each block once and serves the body from held/overlay state. The win materializes when the directive's anchor sits **at or below the prover's own finalized base** (held state) or inside the bounded overlay (cheap re-exec) — §6. **Caveat (G2):** while the standing shadow-check is engaged, steady-state compute is **strictly greater** than today (both backends run every directive) and the shadow **can never retire** (two independently-versioned reth/revm builds), so the "cheaper" regime is the *post-shadow* steady state G2 flags as unreachable in driven mode — carry it as an aspiration, not a delivered win.

**What it does not buy.** It does not improve transition soundness, does not change the on-chain trust model, and does not reduce the worst case (a divergent or cold backend must fall back to the full stateless path). It trades witness-sourcing complexity for **finality-pinned-state-lifecycle complexity** (a bounded durable datadir + an own L1 follower + boot-time reconciliation) — but it **drops** the custom `(height, block_hash)` archive + parent-hash detector + durable rollback engine the old model required.

**The block SOURCE is irreducibly the composer's — "stateful" executes each block ONCE, it does not skip execution (R3/G5).** Two framings must be precise. First, *execution count*: the stateful backend does **not** "serve from already-computed state without re-executing" — it **executes each block exactly once** (at follow-time) and **commits** it to its DB; the win is **once-per-block vs once-per-directive, plus no witnesses**, not zero execution. Second, *block provenance*: it is tempting to imagine the stateful prover sourcing blocks "independently from L1 DA," but it **cannot, for the frontier.** The block being proven is **not published anywhere until the proof signs it** — settlement is the *consequence* of the proof, and the DA record is created *by* settling, so for the frontier the DA is **circular**. Only already-*settled history* has an L1-DA record. Therefore the prover is **irreducibly downstream of the composer for the frontier**, and data-independence for the frontier is **structurally impossible, not merely unwired**. The only independence available is **re-computation of state** (recompute the post-state root from the supplied block, refuse to consolidate unless it matches) — which is exactly why non-state cross-chain facts (outbound A3) **escape it** (G1) and why M3's independence is on the **L1 axis** (own finality / reorg oracle), not the L2-data axis.

**A consequence (R2), CONCEPTUAL: in a *pure-stateful* deployment, `event.block` (copy B) AND the witness would be droppable from the wire.** Copy B exists on the wire as a **vestige of the stateless prover** (no DB → the block bytes are its only input). The stateful follower already holds its executed copy (copy A) in its DB; a directive then needs only `(block_number, block_hash, composition)` to identify which block to serve. **Reading copy B is precisely the bug (G1).** A **hybrid** deployment keeps shipping copy B + witness solely for the stateless fallback path. **Because §9 recommends hybrid-only (pure-stateful is observer-only), this drop-copy-B win is *unreachable in practice*** — present it as a structural point about what copy B *is* (the unbound input the gates must stop reading), not as an actionable deployment saving.

## 4. The abstraction boundary — the `WindowProver` trait

The seam is `validate_window → VerifiedWindow`. We extract a trait whose method matches the current function's contract exactly:

```rust
// new module: crates/eez-proverd/src/backend.rs
#[async_trait::async_trait]
pub trait WindowProver: Send {
    /// Produce the re-executed facts for a CONTIGUOUS window [from..to],
    /// anchor height = window.first().block_number - 1. CONTRACT identical to
    /// today's native-validate (main.rs:624-641, hash bind main.rs:726-735):
    ///   - parent_state_root == backend's committed root at the anchor height
    ///   - final_state_root + per_block_roots from REAL re-execution of event.block
    ///   - sync_per_tx_roots + sync_tx_statuses for the Sync (last) block,
    ///     subject to the no-op soundness guard (validation.rs:409-419)
    ///   - each re-derived block hash == event.block_hash
    /// Err(..) == "I refuse / cannot serve this window" (a real attester refusing).
    async fn prove_window(&mut self, window: &[ControlEvent])
        -> eyre::Result<VerifiedWindow>;

    /// Cheap, side-effect-free routing hint. Keyed on the backend's OWN
    /// finalized/overlay coverage — NOT on a composer-asserted frontier. See §6.
    /// `from-1` is the anchor height the window needs.
    fn serveability(&self, from: u64, to: u64) -> Serve;
}

pub enum Serve {
    Ready,                       // anchor in durable state or inside bounded overlay
    BelowDurable { floor: u64 }, // anchor below own finalized base AND not re-derivable; stateless
    AboveOverlay { up_to: u64 }, // to exceeds own overlay tip / cap; stateless, let follower catch up
    Degraded,                    // own-L1 halted/diverged: force stateless (the fallback floor)
    NotBootstrapped,
}
```

`&mut self` because the stateful impl mutates held state; the stateless impl ignores it.

**Three impls:**
1. `StatelessWitnessBackend { validator_bin, chain_config, work_dir }` — body is the **current `validate_window` verbatim**. `serveability` returns `Ready` for any range (it re-derives the anchor from the witness). This is the always-correct oracle and the **guaranteed fallback floor**.
2. `StatefulFollowerBackend` — §5. A **finality-pinned follower node with its own L1 view**, not a function call.
3. `HybridBackend { stateless, stateful }` — itself a `WindowProver`; `prove_window` runs the pure selector (§6) and delegates. Keeps the call site to one `Box<dyn WindowProver>`.

**Plug-in point.** Replace `main.rs:2071-2085` with a backend constructed once before the directive loop (mirroring the existing `EEZ_COMPOSER_DRIVEN` gate at `main.rs:1597`):

```rust
let mut backend: Option<Box<dyn WindowProver>> = build_backend(&args)?;
// ... at the old call site:
if let Some(b) = backend.as_mut() {
    match b.prove_window(&window).await {
        Ok(vw) => verified = Some(vw),
        Err(e) => { error!(error=%e, "window prove FAILED"); window_ok = false; }
    }
} else { /* observer branch unchanged, main.rs:2080-2085 */ }
```

Nothing else in the directive loop changes shape — `verified: Option<VerifiedWindow>` flows on through the telescope (`main.rs:2129/2133`), the gates, and attest+submit exactly as today.

**What stays byte-identical (the compatibility guarantee):**
- **Wire** (`crates/eez-control-rpc/proto/control.proto`): `ControlEvent` incl. `witness` and `block`; `PostBatch.abi_calldata`; `SlotProof.post_batch_proof` (already `bytes`); `VerifyRange`. The witness stays populated by eez-node for the stateless backend and is *ignored* by the stateful one — purely additive.
- **Public inputs**: `verify_settlement_public_inputs` (`main.rs:820`) over calldata + vkey only — state-agnostic, unchanged.
- **All settlement gates**: consume `VerifiedWindow` + batch + **per-event block RLP (copy B) — the G1 hole, see §8**. This is **NOT** an unchanged/safe compatibility guarantee until those gates are rerouted off copy B: `extract_inbounds(&e.block)` (`main.rs:2295`) and outbound A3 `outbound_user_txs_from_block` (`main.rs:2353`) read **every event's block**, not only the Sync/last block; only #10's `system_tx_flags_from_rlp` (`main.rs:1291`) reads the Sync block.
- **Attest + submit, composer (`ProverDispatch`, `PostedWindows`, `ProofSink`), on-chain**: unchanged.

The contract sees one 65-byte signature over one hash; it cannot tell which backend produced the root. **The new L1 connection (M3) is internal to the prover** — it changes *what the prover trusts as its durable base*, not the wire or the contract.

## 5. Stateful backend internals (`StatefulFollowerBackend`)

> **Scope correction, carried forward.** "Reuse `Deriver::execute_block`" materially understates this. `execute_block` (`deriver.rs:424`) *reads* parent state and returns `(ExecutionData, SealedHeader)` **without committing** (`deriver.rs:558-561`); it discards the `outcome` holding receipts. To *advance held state* you must run the reth engine (`newPayload` + forkchoice) through the committer actor. The stateful follower is an **embedded follower node**.
>
> **Model correction (M1/M2/M3 — this pass).** The old §5 specified a custom `(height, block_hash)` fact archive, a custom feed-native parent-hash reorg detector, and a custom durable rollback engine, *because the prover had no L1 view*. **Under M3 the prover gets its own L1 view, and under M1 the durable boundary is pinned to L1-finalized, so all three of those custom pieces collapse:**
> - the durable rollback engine for optimistic reorgs is **deleted** — optimistic reorgs touch only reth's in-memory tree (Tier A) and are rebuilt by re-execution;
> - the custom parent-hash detector is **replaced** by `eez-l1`'s `L1Watcher` reorg detection + the deriver's `revalidate_index_tail` self-audit, against the prover's own L1;
> - the `(height, block_hash)` archive is **subsumed** by reth's native hash-keyed in-memory tree (overlay) + the durable trie (finalized base). The directive's `event.block_hash` still binds which chain we serve.

**Held state (the new shape).**
- A **durable reth L2 state datadir bounded at the prover's own L1-finalized boundary** (Tier C). This is a genuine GB-scale store but it only ever *advances* under honest L1; `DrivenCheckpoint` persists only scalars (`main.rs:185-195`) and is orthogonal.
- An **in-memory speculative overlay** (Tiers A+B) = reth's in-memory block tree above `finalized`. This is hash-keyed by construction, so a reorg that replaces height `n` makes the old `(n, old_hash)` unreachable automatically — no custom archive needed. The directive carries `event.block_hash = new_hash`, so a stale-chain serve is impossible.
- **The prover's own L1 follower (M3):** `eez-l1`'s `L1Watcher` + read-only `Submitter` + `L1CanonicalHead`, against the prover's **own** `EEZ_L1_RPC_URL` — a node *separate* from the composer's embedded L1 (see "Own L1 view" below).
- A **durable held-root → height locator** for the finalized base (so a restart can re-anchor without re-deriving the whole trie). reth's persisted `safe`/`finalized` num-hash (`block_committer.rs:216/227`) supplies this on boot via `spawn_from_provider` (`block_committer.rs:190`).

**Own L1 view (M3) — why it is required for SOUNDNESS, and how it reuses existing machinery.**

The grounding is the composer-trust finding: today the directive's `from_block = posted+1` where `posted` is the **composer's own** `l1_head.cursor()` snapshot (`composer.rs:390/411`, dispatched at `prover_dispatch.rs:53-62`), and the only L1 datum that could enter `publicInputsHash` is the composer-supplied `pb.l1_block_hash` (`main.rs:840`). The prover verifies *the composer's self-report is internally consistent* — it does not verify L1. That is harmless **only because the prover re-executes everything** (`main.rs:1707-1709`). The moment M1 lets the prover *stop* re-executing below a frontier, the frontier is a trust root, and **a verifier that derives its entire L1 worldview from the entity it verifies is not verifying L1.** This is a soundness loss, not merely a robustness one — hence M3 must land with or before M1.

The machinery to do it already exists and is **reth-free**, factored out of the `Deriver` into the standalone `eez-l1` crate. The `Deriver` (`deriver.rs:42-73`) merely *composes* three `eez-l1` primitives and subscribes to their events — which is exactly why a stateful prover can reuse them against its own L1:

- **`L1Watcher`** (`crates/eez-l1/src/l1_watcher.rs`) owns the L1 connection (an alloy HTTP provider, polled every 500 ms, `POLL_INTERVAL` at `l1_watcher.rs:38`) and fans `L1Event::{NewHead, BatchPosted, Reorg, Finalized}` (enum `l1_watcher.rs:66`) over a broadcast channel (`spawn` `:237`, `subscribe` `:253`). `from_env` reads `EEZ_L1_RPC_URL` + `EEZ_REGISTRY_ADDRESS` + `EEZ_ROLLUP_ID` + `EEZ_L1_REORG_MAX_DEPTH_BLOCKS` (`l1_watcher.rs:168`). It self-contains reorg detection (`poll_cycle` `:290`, `walk_back_to_common` `:714`) and finality (`refresh_finalized` → `eth_getBlockByNumber("finalized")` `:617`). It takes **any** HTTP URL — point it at the prover's own node and it is independent by construction. `BatchPosted` carries the **authoritative** L1 facts the prover today only gets via the composer: `settled_final_state` = "L1's ACTUAL stored root after this batch" (`l1_watcher.rs:122-126`), `settled_count`, `consumed_count`, `claimed_current_state` (`:87-134`).
- **`Submitter` read-side** (`crates/eez-l1/src/submitter.rs`): `scan_batches(deploy_block)` (`:246`) for catch-up and `canonical_l1_hash(number)` (`:280`) for the missed-reorg audit. Built read-only via `SubmitterConfig::from_env_read_only` (`crates/eez-l1/src/config.rs:99`), which installs a deterministic **dummy** poster key (`:143-163`) so a read-only consumer never signs. (`scan_batch_logs` is `pub(crate)` at `submitter.rs:873`; the prover reaches it through the public `Submitter::scan_batches`/`canonical_l1_hash`, or it is promoted to `pub` — a minor packaging change.)
- **`L1CanonicalHead`** (`crates/eez-l1/src/l1_canonical_head.rs:27`) is the pure in-memory confirmed-frontier ledger: `cursor()` (`:43`), `finalized_l2()` (`:48`), `append`/`append_many` (`:111/:128`), `retreat_on_l1_reorg(common_ancestor)` (`:150`), `highest_l2_at_or_below_l1` (`:171`), `set_finalized_l2` (`:183`). Zero reth coupling; already impls `ConfirmedHeadSource` (`:188`). **This IS the prover's Tier-C boundary + L1-reorg-retreat ledger, verbatim.**

The prover reuses the **deriver's own control-flow as a template**: subscribe-first-then-resync ordering, `recovery_resync`/`revalidate_index_tail` audit-by-hash (`deriver.rs:173/192`, probing `submitter.canonical_l1_hash(tail.l1_block)` at `:197` — this is the piece that *verifies* L1 rather than trusting events), and the `handle_event` match (`:707`). What it does **not** reuse is the body that drives a *shared* `BlockCommitterHandle` on behalf of a co-located sequencer (`begin_reconcile`, `retreat_l2_to_cursor` at `deriver.rs:1007`, `reconcile_batch_blocks`) — a standalone prover has its own committer and supplies its own overlay/persistence; it borrows the *decisions* (which block is canonical, which range to retreat), not those reth calls.

**Net for M3:** instantiate `L1Watcher` + read-only `Submitter` + `L1CanonicalHead` against the prover's own L1 RPC, run the deriver's subscribe+resync+audit loop, and replace `from = directive.from_block` (composer-asserted) with the prover's **own** `finalized_l2` as the durable base and its own `cursor` as the overlay floor. That gives an independent finalized boundary, independent inclusion boundary, independent L1-reorg detection, and an independent `settled_final_state` per batch to cross-check against re-execution — i.e. the prover can compute "L1 confirmed L2 up to height H with root R" itself (R from `settled_final_state` or the on-chain `rollups(rollupId).stateRoot`; **H derived by decoding the postBatch calldata** with `eez_payload_codec`, since no L2 height is on chain) and check `R == own_state_root(H)` exactly as the deriver's `check_claimed_state` / `l2_state_root_at` already do (`deriver.rs:1487/1115`).

**Finality-driven persistence (M2) — and the honest correction.** The forkchoice triplet already realizes M2 at the *consensus* layer: `process_sequence`/`process_derive` move only the unsafe head and leave "safe/finalized stay put" (`block_committer.rs:428-431/686-688`); `process_reorg_to` rolls the head back but *reuses* the existing `safe_header`/`finalized_hash` (`:533-566`, comment `:558-563`); `advance_safe_finalized` (`:345/625-640`) is the **sole** mover of safe/finalized, called only from the L1-driven deriver paths (`deriver.rs:931/1016/1046`). **But reth's *physical* persistence is distance-from-head, not finality-driven:** the engine flags are `--engine.persistence-threshold=256` and `--engine.memory-block-buffer-target=128` (`docker-compose.chiado-node.yml:129-130`), which persist canonical blocks to the DB by distance behind head, **independent** of the finalized FCU hash. Nothing in this repo wires finalized→persistence. So M2's "durable = finalized, overlay = in-memory" holds **only while the optimistic span stays inside reth's in-memory window**, and that is enforced by the speculative-depth cap (`Sequencer`, `DEFAULT_MAX_SPECULATIVE_DEPTH = 64` at `sequencer.rs:60`, gauged on `confirmed_head()` = `cursor()`), which is now **ENABLED at 1024 in the live config** (`EEZ_MAX_SPECULATIVE_DEPTH:-1024`, `docker-compose.chiado-node.yml:88`; both running nodes carry 1024; `EEZ_MAX_SPECULATIVE_DEPTH` read at `eez-node/main.rs:410`, the `if depth != 0` enable-guard a few lines below). But **1024 is far larger than reth's `memory-block-buffer-target` (128)** and it is **still gauged on `cursor`, not `finalized`** — so the optimistic head can still outrun the in-memory window, blocks persist while still unsafe, and a later reorg unwinds the DB (the known "head unbounded → reth Headers-table corruption" failure class in memory). The cap is therefore **enabled-but-mis-sized-and-mis-gauged**, not disabled. The reth dep is a **custom fork** pinned to `mediocregopher/partial-persistence-clean` (`Cargo.toml:56-57`) "containing the receipts-reorg truncation fix" — i.e. the reorg-below-persisted path is actively patched, not a stock guarantee.

**Memory-window budget (the M2 enforcement requirement).** Because the durable base is at **finalized** (Tier C), the overlay that must stay in memory spans the optimistic depth **plus the full finality lag**: `head − finalized_l2 = (head − cursor) + (cursor − finalized_l2)`. On Gnosis the finality lag alone is ~64 blocks. So the prover must (a) **size the speculative-depth cap** so `cap + finality_lag < memory-block-buffer-target (128)` (the live `1024` default violates this) — or raise the buffer target above `cap + finality_lag` — and (b) **gauge it against `finalized_l2`, not `cursor`**. Today the cap is **enabled at 1024** but **mis-sized** (1024 ≫ 128) and **mis-gauged** (against `cursor`/inclusion). This is a config/wiring requirement of M1/M2, not new machinery.

**Per-block facts (unchanged crux).** For each canonical block the follower records the post-state root (`per_block_roots`) and block hash. For the **Sync (last) block** it must additionally produce **per-tx facts**, which is new instrumented code:
- `sync_per_tx_roots` (consumed at `main.rs:1316/1292`): snapshot the interim state root after each tx, reproducing native-validate's `pair_roots`.
- **No-op soundness guard, byte-for-byte** (`/home/ubuntu/zisk-patch-stateless/crates/stateless/src/validation.rs:409-419`): emit **empty** `pair_roots` whenever `result.requests` is non-empty **or** withdrawals are non-empty; otherwise emit the full per-tx vector. A follower that naively emits the full vector when native-validate would emit empty hands `proven_root` a strictly larger acceptance set — a real interior-boundary over-acceptance (replay re-arm), latent today only because eez0 blocks carry empty requests/withdrawals. The shadow-check must assert `sync_per_tx_roots` **length** parity, not just value parity.
- `sync_tx_statuses` (consumed at `main.rs:1380`): per-tx receipt success, emitted **unconditionally** (native-validate emits statuses even in the guard branch, `validation.rs:407/416`). **The follower must HARD-REFUSE to attest if it cannot produce `sync_tx_statuses`** — omitting it makes `system_txs_succeeded(None) → true` (`main.rs:914-917`), which is **fail-OPEN**: the backend would *attest* a reverted-system-tx batch the stateless path rejects, with only a log warning. This is the single most dangerous correction in the whole design and is **unchanged** by the new state model.

**Narrowest viable production shape.** Rather than instrument *every* block at production time, the MVP serves the directive **body** `[from .. to-1]` from held/overlay state (`per_block_roots`, `final`, anchor `= state(from-1)` from the durable trie or the overlay) and **re-executes only the single Sync block `to`** on demand with per-tx instrumentation. This captures the dominant saving (the backlog body), confines the per-tx parity risk to exactly one block per directive, and structurally avoids the fail-OPEN **S2** #10 hole (the Sync block is always freshly instrumented → statuses are always present). **It does NOT fix #10's G1 exposure:** the #10 flags are still read from the forged `event.block` (copy B, `main.rs:1291`) and aligned to the spine statuses by only a length check (`main.rs:918-925`), so re-instrumentation alone leaves #10 forgeable — #10 still requires the G1 reroute (below). The full-instrumentation variant is a later optimization.

**Gate-binding caveat (G1, §8 — a hard precondition, not an optimization).** The cross-chain / #10 gates do **not** read the `VerifiedWindow`; they decode the composer's **re-supplied `event.block` (copy B)** directly — `system_tx_flags_from_rlp(window.last().block)` (`main.rs:1291`), `extract_inbounds(&e.block)` (`main.rs:2295`), outbound A3 `outbound_user_txs_from_block` (`main.rs:2353`). The stateful follower executes its **own copy A** and only matches `event.block_hash`; it never re-hashes copy B. So the MVP must **reroute those gates onto copy A** (or the `publicInputsHash`-bound posted DA calldata) — or, as **temporary hardening** (not a co-equal fix; §8.G1), assert `event.block.hash_slow() == event.block_hash` **and** `body.transactions_root == header.transactions_root` **before** the gates run. Without this the byte-identical-`VerifiedWindow` guarantee does **not** extend to escrow-bearing outbound A3 (§8.G1).

**The anchor (corrected for the new model).** OD-5 requires `parent_state_root == state(from-1) == state(settled)`. For a *settling* directive, `from = posted+1 = cursor+1` (inclusion+1, `composer.rs:411`), so the anchor is `state(cursor)`. Since `finalized_l2 ≤ cursor` always, **`state(cursor)` lives in the overlay (the Tier-B finality-lag span), NOT in the durable trie.** Consequence the design must state plainly: **the in-memory overlay is load-bearing for settlement**, not merely an optimistic convenience — losing it forces re-execution of the entire `[finalized..cursor]` span before the next settling window verifies. This is a third reason the memory window must comfortably exceed the finality lag.

**Same `publicInputsHash`.** Unchanged: the stateful path runs the identical `verify_settlement_public_inputs` (`main.rs:820`) over `PostBatch.abi_calldata` — state-agnostic — so the signed 32-byte digest is bit-identical to the stateless path's.

**Bootstrap (corrected).** `backfill_block` (`main.rs:419`) only *fetches* witness + raw block; it executes nothing, so it is **not** a stateful-bootstrap vehicle. Cold bootstrap with a local reth: seed the durable base from the prover's **own** reth persisted `safe`/`finalized` num-hash via `spawn_from_provider` (`block_committer.rs:190/216/227`) — the follower-style boot anchor (`eez-follower/src/main.rs:75-126` is the working template). Cold bootstrap with **no** local reth = unavoidable full re-derivation `[1..finalized]` by *executing* each block, and that cost is **non-uniform**: reth reverse-state reconstruction is O(distance-from-tip) (memory: recent witness ~0 s, block-1 hangs >5 min), so re-deriving deep history from the archive is impractical — state this as the one-time bootstrap cost and prefer seeding from a persisted datadir. A wrong `EEZ_INITIAL_STATE_ROOT` remains a silent mis-anchor footgun (memory: `0x037cf8a5` gotcha); mitigation is the **hard boot-time gate** — require held `state(finalized)`/`state(settled)` to equal a stateless-verified anchor on at least one *settling* window before any stateful attestation is trusted. **Limitation (G5):** that gate validates via a **stateless (witness/composer-data) re-exec**, so it is **composer-frame, not M3-independent** — it pins the held trie to the composer's view, not to an independent re-derivation; acknowledge it as such (§12 G5). During bootstrap the hybrid routes **all** directives to stateless, so liveness never pauses.

## 6. Directive handling — range → increment, gaps, retreats, all-or-nothing

**The corrected selector keys on the prover's OWN frontier, never the composer's.** The directive `from = settled + 1` (`composer.rs:411`, dispatched at `prover_dispatch.rs:53-62`) is composer-asserted and *lags the tip*. The selector decides serveability against the prover's own `finalized_l2`/`cursor` and the bounded overlay — and critically, **the routing decision never gates the attestation** (§8): an uncovered/lagging case routes to the always-sound stateless backend, it does not refuse.

```rust
fn select_backend(from: u64, to: u64,
                  own_finalized: u64,    // prover's OWN L1-finalized L2 (Tier C)
                  own_overlay_tip: u64,  // prover's OWN overlay head
                  overlay_cap: u64,      // own speculative cap, < memory-buffer-target − finality_lag
                  l1_healthy: bool,      // own L1Watcher not halted/diverged
                  bootstrapped: bool) -> Route {
    if !bootstrapped || !l1_healthy        { Route::Stateless }            // boot / degraded floor
    else if to > own_overlay_tip           { Route::StatelessAndCatchUp }  // ahead of overlay
    else if to <= own_finalized            { Route::Stateful }             // whole window already durably held
    else if to - own_finalized > overlay_cap { Route::Stateless }          // overlay would exceed memory
    else                                   { Route::Stateful }             // durable base + overlay cover it
}
```

**(Underflow guard + coverage invariant.)** The `to <= own_finalized` short-circuit is not merely an optimization: without it `to - own_finalized` **underflows** (`u64`) whenever the prover is already finalized **past** the requested window (`to <= own_finalized`, a window entirely below the durable base) — the guard (equivalently `to.saturating_sub(own_finalized)`) makes that case serve from durable state. **Coverage invariant:** the stateful backend can serve `[from..to]` **iff** the anchor-to-endpoint span `[from-1 .. to]` lies within held coverage (`≤ own_finalized`) or bounded-overlay coverage (`≤ own_overlay_tip` and within `overlay_cap` of `own_finalized`); outside that span, route stateless.

- **Steady state (anchor at/below own finalized, or inside the bounded overlay):** serve the body from held/overlay state and freshly re-execute only the Sync block (MVP). Near-free.
- **Ahead of overlay (`to > own_overlay_tip`):** the prover's follower fell behind the very tip; route to stateless (attest now from witnesses → liveness held) and let the follower catch up off the critical path. **This is the steady-state lag case (c): the gap is overlay, not a gate.**
- **Overlay would exceed memory (`to − own_finalized > cap`):** consolidation can't cover it without persisting un-finalized blocks (the DB-unwind hazard); route to stateless. Expected, not an error.
- **Degraded (`!l1_healthy`):** own L1Watcher halted (`ReorgTooDeep`) or persistently diverged → **force stateless** (the guaranteed fallback floor). Never keep consolidating on a frozen/orphaned base.

**The own-L1 view is a non-blocking, monotonic lower bound on durability — never a gate on attestation.** Healthy → it lets the prover skip re-execution below its own *finalized* base. Lagging/halted/diverged → it transparently degrades to today's full stateless re-execution. This is the net rule of the whole design.

**Per-directive backend pinning.** `prove_window` is invoked **per max-window chunk** (`main.rs:2071`), but the OD-5 batch anchor is captured from **chunk 1's** re-executed parent (`batch_anchor_root = Some(vw.parent_state_root)`, `main.rs:2129`) and every later chunk telescopes against the running `prev_chunk_final_root` (`main.rs:2133`). You **cannot flip backends mid-directive**. The selector decides once per directive and pins one backend for all chunks. If chunks ever split across backends, the inter-chunk continuity check (`vw.parent_state_root == prev_chunk_final_root`, `main.rs:2133-2141`) is the fail-closed guard — but the design pins to avoid relying on it.

**All-or-nothing window.** Preserved identically. For a held/overlay-served happy path the facts are already-committed canonical results; only the **durable attested-frontier pointer** advances, and only at the settling boundary. A gate reject leaves the cursor where it was (the existing fail-closed invariant); the held trie is not rolled back by a *gate* reject (it follows canonical), only by a *finality reversion* (§7).

## 7. Reorg / recovery / state lifecycle

This was the weakest part of the original design, and the new model **inverts the difficulty**: the dominant reorg becomes trivial, and only one rare class remains hard. Three distinct events must be kept separate, plus an explicit L1-divergence table.

**(a) L2 optimistic reorg (the dominant one — now a NON-event for durable state).** The composer's optimistic L2 chain rolls back (`recover_failed_batch → committer.reorg_to`). Under M1 this happens entirely **above** the prover's own L1-finalized base — in reth's in-memory tree (Tiers A/B). The follower re-executes the new chain into the overlay; **no durable rollback occurs.** This is the single biggest simplification of the new model: the old §5/§7's custom feed-native parent-hash detector + custom durable rollback engine are **deleted** for this case.

**(b) L1 reorg of the prover's OWN L1 (split by depth against `reorg_max_depth = 62`).**
- **(b1) shallow, ≤62 (normal).** The prover's `L1Watcher` emits `L1Event::Reorg`; the prover runs `retreat_on_l1_reorg(common_ancestor)` (`l1_canonical_head.rs:150`) — drops batch records above the ancestor, retreats `cursor`, clamps `finalized_l2` only if it would cross — then re-derives the rolled-out span as overlay. **Because the durable base is at finalized (Tier C) and the reorg is in Tier B (included-but-not-finalized), the durable base does not move.** If the rolled-out batch is genuinely canonical (the prover was on a transient minority fork), the watcher re-observes its `BatchPosted` on re-convergence and re-advances. M1 holds.
- **(b2) deep, >62 → finality reversion → `ReorgTooDeep`.** **This is the one residual hard case** — the only event that can move the **durable (finalized) base** backward. Two problems the design must address:
  1. *Soundness.* "finalized only ever advances" is an L1-honesty **assumption** (economic finality), not a code guarantee — `retreat_on_l1_reorg`'s `min`-clamp (`l1_canonical_head.rs:158`) proves the code itself can move `finalized_l2` backward. A consolidated prover that ignores this keeps ECDSA-signing on an orphaned base.
  2. *The live code currently MISHANDLES it.* The watcher's `poll_cycle` returns `L1Error::ReorgTooDeep` (`l1_watcher.rs:380/448`), but the run loop **swallows any `poll_cycle` error with a WARN "will retry next tick" and continues** (`l1_watcher.rs:276-285`). So a too-deep reorg produces **neither a clean halt nor a `Reorg` retreat** — the watcher livelocks, no `Reorg` event is emitted, and `retreat_on_l1_reorg` (the only code that clamps `finalized_l2` back) is unreachable. **Correct behavior for the prover:** make `ReorgTooDeep` a real halt/operator-intervention state (the run loop must NOT swallow it), and on halt **DEGRADE to full stateless re-execution + raise an alarm** — never deadlock, never keep attesting on a frozen base. Stateless re-execution is always sound and (modulo witnesses) always live: the safe fallback floor.

**(c) L1-settlement retreat / steady-state lag (NOT an L2 reorg).** The composer's L1 is ahead of the prover's own L1 (the composer's embedded node confirms over loopback instantly, `docker-compose.chiado-node.yml:50`; the prover's independent node observes via 500 ms polling + propagation, `l1_watcher.rs:38`), so the prover's durable base **structurally trails**. The gap `[own-finalized .. directive-implied]` is **overlay**: re-execute, attest normally, catch up via own polling. **Lag MUST NOT gate attestation.** Bound it with the own speculative-depth cap (above). A dead/stuck own-L1 ⇒ overlay grows ⇒ fall back to stateless rather than ballooning memory.

**The L1-divergence behavior table (the core of the adversarial stress).** Let "own-L1" = the prover's independent L1 follower; "directive" = the composer-asserted range.

| Case | Condition | Correct behavior | Durable base moved? | Soundness |
|------|-----------|------------------|---------------------|-----------|
| **(a) lag — directive ahead of own-L1** | deferred-post: the batch is attested *before* it lands on L1 (chicken-and-egg) | **ATTEST** from overlay re-exec; advance durable base only when own `L1Watcher` emits `BatchPosted` (`deriver.rs:759→931`). Never refuse on lag. | No | Sound — OD-5 anchor `state(posted)` is re-derivable in the overlay; gating here would **deadlock** the deferred-post flow |
| **(b1) own-L1 reorg ≤62** | rolls out an included-but-not-finalized batch | `retreat_on_l1_reorg` (`l1_canonical_head.rs:150`); demote span to overlay; re-confirm on re-convergence | No (base is at finalized, below the reorg) | Sound — by construction the finalized base can't move |
| **(b2) own-L1 reorg >62 / finality reversion** | crosses the finalized boundary → `ReorgTooDeep` | **DEGRADE to full stateless** + alarm; make the halt real (`l1_watcher.rs:276-285` must stop swallowing it) | **YES — the only case** | Residual hard case; currently a silent livelock |
| **(c) own-L1 lags composer (steady state)** | own node trails by polling + propagation | gap is overlay: re-execute, attest, catch up; own depth-cap bounds it | No | Sound — own-L1 is a monotonic lower bound on durability, never a gate |
| **(d) permanent disagreement / wrong fork** | own node on a different chain than the settling fork | **NEVER consolidate** the disputed region (perpetual overlay = degrade to stateless there); alarm; `revalidate_index_tail` per-batch `canonical_l1_hash` probe (`deriver.rs:197`) detects it | Frozen at last agreed point | **Timeless: fork-AGNOSTIC, stays sound** (see §8). **Bound: self-DoS fail-closed**, no theft |

**Single-writer ownership.** The background follower *owns* all held-state mutation (advance + the Tier-B overlay re-derive); `prove_window` only reads/serves. The hybrid router drives the handshake and pauses the follower during any unwind — it must not assume a separate task "already retreated."

**Crash-consistency.** The trie commit is reth's own DB write behind the committer actor; there is **no hook** to atomically order a prover-side pointer against reth's commit. Do **boot-time reconciliation**: read the actual reth persisted `safe`/`finalized` (`spawn_from_provider`, `block_committer.rs:190/216/227`), compare to the durable attested-frontier pointer and to `DrivenCheckpoint` (`main.rs:185-195`), and roll one to the other. Three durable artifacts (reth datadir, follower finalized/locator, `DrivenCheckpoint`) must agree; recommendation: the **reth datadir's finalized tip is authoritative for held state**, `DrivenCheckpoint` for **attested progress**, re-derived against the datadir on recovery.

**The follower is a second ring subscriber.** It advances a GB trie one `newPayload`+FCU at a time, slower than the directive loop, so under bursts it lags and the feed can cut it with `DATA_LOSS` (`control_feed.rs` disconnect-on-overrun). It needs its own backfill + contiguity + resync path, and the ring sizing rationale (`control_feed.rs:89-113`) — written for one consumer — must be re-evaluated for two. **But note:** the follower no longer needs a custom reorg engine; reorg handling is reth's in-memory tree (optimistic) + the own `L1Watcher` (L1) — the deriver/follower pattern, not a bespoke detector.

## 8. Soundness-equivalence argument (the crux)

**What the contract enforces.** Only `ecrecover(publicInputsHash, proof) == signer` (`ECDSAProofSystem.sol:30-31`) over a `publicInputsHash` rebuilt from full calldata (`EEZ.sol:634/636`); `_applyStateDeltas` only telescopes `config.stateRoot == delta.currentState` (`EEZ.sol:1006`) and never validates `newState`. So the signed 32-byte hash, from the registered key, **is** the entire on-chain contract.

**Hash identity (solid).** `publicInputsHash` is recomputed in `verify_settlement_public_inputs` (`main.rs:820`, hash at `main.rs:846`) from `pb.abi_calldata` + vkey + `l1_block_hash` only — no state, no witness — and `ProofSink::verify_attestation` recovers over that hash against the single registered attester. Both backends sign the **same** digest with the **same** key; at the signature layer the two attestations are literally indistinguishable on-chain. **Unchanged by the new state model** (state-agnostic).

**Transition soundness is delegated off-chain to the gates**, which bind only to re-executed facts in `VerifiedWindow`: OD-5 anchor, endpoint, interior proven-root (`main.rs:1316`), #10 (`main.rs:1380`), inbound bijection, outbound A3 (`outbound_gate.rs`). **— except that several of them do not actually read `VerifiedWindow`; they read the composer's raw `event.block`, which the stateful backend never binds. That is G1, the one true soundness blocker.**

**G1 — THE soundness BLOCKER: `event.block` is not preimage-bound under the stateful backend.** The "bind only to re-executed facts in `VerifiedWindow`" claim above has a hole that is benign for the stateless backend and **fatal** for the stateful one. Several gates do **not** read the `VerifiedWindow` — they decode the **composer-supplied raw `event.block` RLP** directly: #10 system-tx flags via `system_tx_flags_from_rlp(window.last().block)` (`main.rs:1291`), inbound extraction via `extract_inbounds(&e.block)` (`main.rs:2295`), and **outbound A3** via `outbound_user_txs_from_block` over `e.block` (`main.rs:2353`). The stateless backend is sound **only** because `validate_window` re-executes that *literal* `event.block` and asserts `reseal.hash == event.block_hash` (`main.rs:726-735`) — a binding of the bytes-the-gates-read to a verified result that exists **nowhere else** (intra-window contiguity uses the `parent_hash` *field*, not a re-hash, `main.rs:2057`).

A stateful follower builds blocks from its **own** held state, and a directive only needs `(block_number, block_hash)` to select which block. It therefore matches `event.block_hash` but **never re-hashes the `event.block` bytes the gates consume.** So a tampered `event.block` that carries the *real* `block_hash` field in its header **passes every check while the gates run on forged bytes.** The **copy-A / copy-B** framing (R1) makes the leak precise — note that the stateful backend is **not** skipping execution; it executes each block once and commits it. The gap is *which* bytes:
- **copy A** = the bytes the follower actually *executed* and committed at follow-time (**bound**, but the gates never read it);
- **copy B** = the directive's *re-supplied* `event.block`, read by the gates at verify-time (**unbound**);
- **executed = copy A, gates read = copy B; nobody checks copy B == copy A at verify-time.**

This is **forgery, not liveness** (R3: an independent verifier must check with **its own** copy; feeding the gates copy B — the bytes of the very party being verified — is the conceptual leak, the same independence principle M3 enforces on the L1 axis). The decisive case is **outbound A3**: it authorizes an L1 escrow payout (`config.etherBalance -= decrement`, `EEZ.sol:1010`), but the canonical outbound L2 user tx **reverts** in plain re-execution (`outbound_gate.rs:22-30`), so its authorization is **invisible to the state-root chain** — there is **no `StateRootMismatch`/OD-5 self-reject** to catch it (the "self-rejects via its own gates" guarantee covers only state-root-captured facts, and an escrow authorization is not one). #10 is defeated the same way: the flags come from `event.block` (`main.rs:1291`) while the statuses come from the spine, aligned only by a length check (`main.rs:918-925`).

**Fix — THE clean STRUCTURAL fix (copy A) vs. the TX-SCOPED binds (a hard precondition before any stateful output is trusted).** **The clean, durable, future-proof fix is STRUCTURAL: route the cross-chain/#10 gates onto the follower's OWN FULL EXECUTED BLOCK (copy A) — the bytes the backend actually executed and committed — never the re-supplied copy B.** This is **structural** (the gates physically cannot read copy B), **future-proof** (it holds for **any** body field a future gate may read, not just txs), it is what lets a **pure-stateful** deployment **drop copy B from the wire** entirely (the bandwidth win and the "an independent verifier checks with its OWN copy" principle, R3), and it is the **unique** fix in that class. **Two other binds are TX-SCOPED — sound for TODAY's gates but NOT future-proof — and they GROUP TOGETHER with each other, not with copy A:** (i) the **tx-root cheap-patch** (before running the gates, decode `event.block` and assert `hash_slow() == event.block_hash` **and** `body.transactions_root == header.transactions_root` — a bare keccak is **insufficient**, `hash_slow` reseals the header as-is, so the tx set must be independently pinned to the sealed root); and (ii) **routing the gates onto the `publicInputsHash`-bound posted DA payload.** The DA payload is **NOT** a full canonical block or header — it is `tagByte ‖ rlp([blockTxCounts, transactions, l2_entries, …])` (`crates/eez-payload-codec/src/lib.rs:4`, built at `composer.rs:3178`): it carries the **tx lists + L2 entries** (bound to `publicInputsHash`) and **nothing else of the body**. So routing the gates onto it binds the **txs** — the **same completeness class as the tx-root cheap-patch** — and is **NOT** future-proof for any non-tx body field the way copy A is. Both tx-scoped binds **are** cryptographically sufficient for **today's** gates, which read only `txs`: `hash_slow(B) == event.block_hash == hash(A)` ⇒ (collision resistance) `B.header == A.header` ⇒ same `transactions_root`; plus the body tx-root check ⇒ `B.txs == A.txs`. But both are **fragile**: (a) they bind **only the txs** — any **future** gate reading a non-tx body field (withdrawals / requests / ommers) needs its **own** root-check or the full copy-A routing; (b) the tx-root variant depends on the bind-decode being **byte-identical** to the gates' own decode; (c) the tx-root variant is a **guard that must run before EVERY gate** and can be **bypassed by any new code path** that forgets it; (d) both **keep copy B on the wire**, forfeiting the drop-copy-B / independence win. Note the tx-root check and the external reviewer's "**cryptographically prove copy B == copy A**" are the **same mechanism at different completeness levels** — the tx-root-only version is the **partial** form; a **complete bind** (the header **plus every body root the gates read**) is **sound but still a guard**, versus **structural** copy-A routing. **The split the plan rides on: Phase 1 = a COMPLETE bind for today's tx-only gates** — either tx-scoped form above (the `hash_slow()` + `transactions_root` cheap-patch, OR routing the gates onto the `publicInputsHash`-bound DA payload), both **stateless-safe** and landing **before any stateful code (§11 Phase 1)**; **Phase 3 = the STRUCTURAL copy-A routing** (the follower's full executed block, future-proof for any body field) that **completes with the follower (§11 Phase 3)** and **must be in place before any stateful OUTPUT is trusted / signed / settled (Phase 4)**. **G1 is the single true soundness blocker of this whole design.**

**The two relaxation holes (S1/S2) — unchanged and still load-bearing.** The "fails its own gates, so worst case is a missed attestation" argument holds for *divergences* but **not for relaxations**, where the stateful facts are a *superset* of native-validate's, making a gate pass that native-validate's would fail:
- **S1 — `pair_roots` no-op guard.** native-validate returns **empty** `pair_roots` when a block has non-empty requests/withdrawals (`validation.rs:409-419`); a follower emitting the full per-tx vector hands `proven_root` (`main.rs:1316`) a strictly larger set — a real settlement-soundness divergence (replay re-arm), latent today only because eez0 blocks have empty requests/withdrawals.
- **S2 — `tx_statuses` omission is fail-OPEN.** `system_txs_succeeded(None) → true` (`main.rs:914-917`); a follower emitting `None` *attests* a reverted-#10 batch the stateless path rejects.

Both are **relaxations, not divergences**, closed by **construction** (the no-op guard byte-for-byte; hard-refuse if `sync_tx_statuses` absent) **plus** a hardened shadow-check (length-parity, not just value-parity), a **hard precondition** for trusting any stateful attestation.

**Acceptance-set asymmetries (P1/P2/P3/S3) — the "byte-identical" claim must be downgraded, unchanged.** Even with S1/S2 closed, the backends do not share an identical acceptance set:
- **P1:** `execute_block` is a *builder*, not a *validator* — it rebuilds the header (timestamp `= parent.timestamp + l2_block_time`, etc.) rather than *taking* it. Equivalence holds only for blocks the eez composer built (the Sync-block-timestamp landmine in memory).
- **P2:** native-validate runs full consensus validation the follower's hash-bind does not independently reproduce.
- **P3:** native-validate is a **separate binary from a separate repo** (`/home/ubuntu/zisk-eth-client` → `zisk-patch-stateless`, zeth `SparseState`), independently versioned from the reth/revm the follower advances (memory records a real revm-34→38 EIP-2935 divergence). "The same reth STF" is **false** — two reth/revm builds; the per-tx `pair_roots` path is computed against a reth *full* MPT, not native-validate's `SparseState`.
- **S3:** `parent_state_root` provenance differs — native-validate reads it from the witness's parent header; the follower's held/overlay root is always present.

**The NEW soundness dimension the old doc omitted: consolidation turns the composer cursor into a trust root.** Separate from STF bit-parity (above), M1 introduces a soundness question the *stateless* prover does not have. Today the composer cursor is provably "only a resume HINT … a wrong H cannot make a bad batch attest — it fails OD-5 → reject" (`main.rs:1707-1709`), because the prover re-executes everything. **M1's consolidation is precisely what converts that hint into the trust root for every future attestation.** If the consolidation frontier came from the composer (no M3):
- *Undetected-L1-reorg / orphaned-base.* A composer that fails to signal a reorg (lag/partition/bug/malice) pins the prover's durable base to orphaned L1 history. Having consolidated, the prover can no longer self-heal by re-derivation and keeps signing windows anchored on a base it can no longer falsify. The on-chain `StateRootMismatch` (`EEZ.sol:1006`) is only a **partial** backstop — it protects the contract's *stored root* from a mismatched `currentState` (forged base self-DoSes), but it does **not** make the prover an independent verifier: an attestation produced on a composer-fed base is a deterministic function of composer inputs, so the "independent, separately-keyed second check" collapses to "the composer's self-report is internally consistent." **That is the soundness (not robustness) loss M3 closes.**

Therefore **M3 is a HARD PREREQUISITE that must land with or before M1.** Introducing consolidation without an independent prover L1 is a soundness **regression** the current stateless design does not have. (The codebase's own "self-DoS only" framing for `l1_block_hash` — `control.proto:97-103` — is correct for the *stateless* prover and protects the *stored root*; it does **not** establish that a *consolidating* prover on a composer cursor is sound.)

**Divergence soundness under M3 (the (d) cases, from the table).**
- **Timeless deployment (current): the attestation is L1-fork-AGNOSTIC and stays sound under permanent disagreement.** Timeless `blockNumber=0` folds NO L1 facts — `getTimestampAndBlockHash(0) = (0,0)` (`Rollup.sol:135-137`), and the prover hard-refuses any bound batch (`main.rs:831-836`). A signed attestation certifies "this state transition is valid," not "on fork X"; the on-chain `StateRootMismatch` backstop means it can only apply where the stored `currentState` matches. So under permanent disagreement the prover **may keep attesting valid re-executed windows soundly** — it must merely **NEVER consolidate** (trust as durable) any region its own L1 doesn't confirm. The durable base freezes at the last agreed point; everything above is perpetual overlay = the prover degrades to stateless for the disputed region.
- **Bound deployment (future anti-replay): self-DoS, fail-closed, by design.** If M3 enables anti-replay (fold `blockhash(N)` from the prover's own L1, the precondition the code is waiting for at `main.rs:817-818`), permanent disagreement means the prover folds `blockhash(N)` from its fork, the `publicInputsHash` mismatches what settles, and the frontier cannot advance — the intended fail-closed (no theft, only liveness loss). Pair it with an operator alarm + a timeless-fallback escape hatch.

**The new liveness coupling — soft by default, hard in exactly two places.** Independence does introduce a "prover-L1 must keep up" coupling. It is **soft (optimization-only) by default**: a stalled own-L1 only makes the prover slower (it degrades to stateless), never stuck. It becomes **hard** only when (#1) bound settlement folds the anti-replay nonce from the prover's L1 (agreement with the settling fork becomes a settlement precondition — the deliberate anti-replay-for-L1-liveness trade), or (#2) consolidation is made *mandatory* (e.g. to bound memory). **Recommend AGAINST #2:** keep consolidation a strict optimization with a stateless fallback, bound the overlay with a depth cap, degrade to stateless on lag-past-cap / `ReorgTooDeep` / persistent divergence.

**One more honest limit: independent L1 VIEW, but no independent L2 DATA.** Witnesses still come from the composer's L2 RPC (`EEZ_L2_RPC_URL`, `main.rs:419`). Under permanent disagreement (d) the prover can **DETECT** (refuse to consolidate, alarm, fail-closed) using L1 facts alone — and detection is what closes the soundness gap — but it may be unable to **re-derive** the alternate fork's history. Independent re-derivation additionally needs an independent L2 data/witness source: a separate, harder follow-up, **not** assumed by M3.

**Conclusion.** On-chain indistinguishability is **true at the signature layer** and **false at the acceptance-set layer**. Both backends produce a byte-identical `VerifiedWindow` *when both accept*. **The old claim that a divergent stateful backend always "self-rejects via its own gates and degrades to a recoverable liveness gap" is CORRECTED: it holds ONLY for state-root-captured facts.** The cross-chain gates (esp. outbound A3) read the composer's re-supplied `event.block` (copy B) and authorize facts — an L1 escrow payout — that `final_state_root` does **not** capture, so a forged `event.block` yields a **fully-correct `VerifiedWindow` with no self-reject**: that is **forgery (escrow loss), not a liveness gap** (G1). For *state-root-captured* divergences the old guarantee still holds (self-reject → recoverable liveness gap the hybrid covers with stateless). The two relaxation holes (S1/S2) are closed by construction; STF parity (P1/P3) is maintained by a **standing, continuous** shadow-check with auto-demote-to-stateless; **the `event.block` binding hole (G1) is closed by routing the gates off copy B onto the follower's full executed copy A — the clean, structural, future-proof fix; the `publicInputsHash`-bound DA payload and the tx-root check are TX-SCOPED binds (a complete bind for today's tx-only gates, not future-proof) (§8.G1) — the one true soundness blocker, whose tx-only gate-input bind must land before any stateful code (§11 Phase 1) and whose full structural copy-A wiring completes with the follower (§11 Phase 3) and must be in place before any stateful output is trusted/signed/settled.** And the consolidation-trust soundness requirement — that consolidation must trust the prover's *own* L1, not the composer's — is closed by M3, which must land with or before M1.

## 9. Dual-mode coexistence

**Same attester key, content-keyed frontier.** Both backends sign the **identical** `publicInputsHash` with the **same** registered key. The composer's `mark_attested` is content-keyed and idempotent; the frontier advances exclusively via that content key. So stateless and stateful attesters are indistinguishable to composer and L1.

**Intra-process vs fleet.** Within one hybrid process the router picks **exactly one** backend per directive — no intra-process "whichever lands first wins" race; that applies only across a *fleet* (a separate pure-stateless daemon sharing the key as a liveness backstop). Config selects the backend like the existing `EEZ_COMPOSER_DRIVEN` gate (`main.rs:1597`): `--prover-backend {stateless|hybrid}`.

**Pure-stateful mode is removed / observer-only.** The `AnchorMismatch` retreat-and-re-derive recovery (`classify_settlement_chain`, `main.rs:1277`) is a stateless-re-execution concept with no stateful analog (the held root is what it is). A pure-stateful daemon cannot recover from a retreat or a `ReorgTooDeep`/divergence, so **only hybrid is safe**; do not offer `--prover-backend stateful` except as an observer.

**Empty-heartbeat-hash collision.** `mark_attested` resolves the *widest unresolved* window matching the signed hash, and several unresolved windows can share a near-constant empty-heartbeat hash. Two attesters racing the same hash that maps to *different* windows can resolve the wrong one. Pre-existing; dual-attest increases the rate — note as a coexistence risk, not a regression. (Connects to the N=0 anti-replay sentinel: M3's own L1 is the precondition to activate `blockNumber = N`, which makes the hash unique per batch **and** closes the never-expiring-signature replay vector — §8 hard-coupling #1.)

**Why not a second key (now).** A second registered attester folds a second vkey into `publicInputsHash`, making it a multi-PS batch the prover's single-PS gate hard-refuses (`main.rs:828`) and touching the on-chain registry. That is the future zkVM migration (§10), not dual-mode coexistence.

## 10. The real-zkVM / continuations future path

The `IProofSystem.verify(bytes,bytes32) → bool` interface (`IProofSystem.sol:15`) plus the multi-PS threshold machinery already make a SNARK prover a **second registered proof system**, not a protocol fork. The contract-side claims check out: the single-PS gate is real (`main.rs:828`), settlement is timeless-only (`blockNumber != 0` bails, `main.rs:831-836`), and `SlotProof.post_batch_proof` is already `bytes`.

**What changes on-chain:** register a SNARK verifier as a second `IProofSystem` (vkey = imageId) under the rollup threshold, ramping 1 → 2 → SNARK-only. **Off-chain (three small edits):** relax the single-PS gate (`main.rs:828`); make `apply_proof` indexed per PS; make `verify_attestation` PS-type-aware.

**The deep correctness item:** the inbound-bijection and outbound-A3 gates are trusted **off-chain** today (sound only under the ECDSA trust model). A trustless SNARK must migrate them **into the circuit**.

**Pragmatic intermediate:** ship a **stateless** SNARK first (re-prove each window from witnesses inside the zkVM, committing the existing `publicInputsHash` as the single public input) — trustless and coexisting immediately — and defer the stateful continuation as a proving-cost optimization, *not* a correctness prerequisite. **Distinguish clearly:** the near-term stateful backend of §5 is a *native-reexecution attester* with the *same ECDSA attestation* whose durable base is now pinned to the prover's own L1-finalized view (M1/M3); a stateful zkVM is a *different artifact* whose state continuation is a proving-cost optimization layered on the trustless stateless SNARK. **M3's independent L1** is also the precondition for **bound** settlement / anti-replay in either world (§8 hard-coupling #1).

## 11. Phased implementation plan

Each phase is shippable and revertible; the smallest viable first increment is Phase 0+1. **The plan closes the soundness holes BEFORE any stateful component is trusted, and brings the stateful backend online as an UNTRUSTED OBSERVER before it is ever in the settlement path.**

- **Phase 0 — Trait extraction (small, zero behavior change).** Add `trait WindowProver` + move `VerifiedWindow` into `backend.rs`; wrap the current `validate_window` body verbatim as `StatelessWitnessBackend`; route the single call site (`main.rs:2071-2085`) through `Option<Box<dyn WindowProver>>`. Unit-test byte-identical output. Mirrors `EEZ_COMPOSER_DRIVEN` (`main.rs:1597`).

- **Phase 1 — Close the soundness holes early (STATELESS-SAFE; hard preconditions for trusting any stateful attestation).** Both holes below are **safe on today's stateless path** (a no-op there, since statuses are always present and copy A == copy B), so they ship **now**, before any stateful code — and both are **hard preconditions** that must be closed before any stateful attestation is ever trusted.
  - **(G1 — a COMPLETE bind for today's tx-only gates; the one true soundness blocker.)** The cross-chain / #10 gates decode the composer's re-supplied `event.block` (copy B) — `system_tx_flags_from_rlp` (`main.rs:1291`), `extract_inbounds` (`main.rs:2295`), outbound A3 (`main.rs:2353`) — which a stateful follower would never re-hash. Land a **tx-scoped** bind now — either route those gates onto the **`publicInputsHash`-bound posted DA payload** (which carries the tx lists + L2 entries, `crates/eez-payload-codec/src/lib.rs:4`, built at `composer.rs:3178`), or add the **`hash_slow()` + `transactions_root` cheap-patch** — both bind **only the txs** today's gates actually read, are **stateless-safe**, and are a **COMPLETE** bind for those tx-only gates (§8.G1). Neither is future-proof: the clean, durable, **structural copy-A routing** (future-proof for any body field) lands in **Phase 3** once the follower's executed copy A exists. **STATELESS-SAFE:** on today's stateless path copy A == copy B (the witness re-executes the literal `event.block` and binds `reseal.hash == event.block_hash`, `main.rs:726-735`), so the reroute/bind is a **no-op** with zero behavior change. This is **escrow forgery, not liveness** (§8.G1) — **the one true soundness blocker of the whole design**, and the **tx-only bind must land before any stateful code.**
  - **(S2 — make a missing `sync_tx_statuses` a HARD failure where the settlement gates depend on it.)** Today `system_txs_succeeded(None) → true` is **fail-OPEN** (`main.rs:914-917`): a backend that cannot produce `sync_tx_statuses` would *attest* a reverted-system-tx (#10) batch the stateless path rejects, with only a log warning. Make a missing `sync_tx_statuses` a **hard refusal** wherever the #10 gate consumes it (`main.rs:1380`). **STATELESS-SAFE:** native-validate emits statuses **unconditionally** (`validation.rs:407/416`), so on today's path they are always present and the change never fires — but it is a **hard precondition** before any stateful attestation, which can produce `None`.

- **Phase 2 — Independent prover L1 follower (M3) + health/degrade — the gating dependency for CONSOLIDATION.** Instantiate `eez-l1`'s `L1Watcher` + read-only `Submitter` (`from_env_read_only`, `config.rs:99`) + `L1CanonicalHead` against the prover's **own** `EEZ_PROVER_L1_RPC_URL` (a node *separate* from the composer's embedded L1). Reuse the deriver's subscribe→`recovery_resync`→`revalidate_index_tail` audit loop (`deriver.rs:173/192/197`). Deliverables: an independent `finalized_l2`/`cursor`, independent `BatchPosted`→`settled_final_state`, independent L1-reorg detection, and a **real `ReorgTooDeep` halt** (fix the swallow-and-retry at `l1_watcher.rs:276-285`) that degrades to stateless. **M3 is the prerequisite for CONSOLIDATION, not for the observer:** the Phase-3 observer does **not** consolidate, so it can run against the composer cursor; **M3 must land before any mode that consolidates (Phase 4)** — it is the soundness prerequisite for converting the composer frontier into a trust root, not an add-on.
  - **(G4 — own-L1 health must be detectable; ships WITH M3, a Phase-2 blocker.)** The watcher run loop swallows **every** `poll_cycle` error with WARN "will retry next tick" (`l1_watcher.rs:276-285`), not just `ReorgTooDeep`. On an RPC outage/desync the `cursor`/`finalized_l2` **freeze, no error propagates, `l1_healthy` stays `true`,** and a frozen own-L1 is **indistinguishable from honest lag** — so the prover keeps consolidating on **stale L1 finality** and M3's independent verification is **silently gone** (finality is polled only ~12 s, `FINALIZED_REFRESH_TICKS`). Mitigation: compute `l1_healthy` from a **finality-age / liveness probe** and **propagate `poll_cycle` errors as a `Degraded` signal**; M3 must ship with this, not just the `ReorgTooDeep` halt.

- **Phase 3 — Stateful backend as OBSERVER / SHADOW only (large; the real work — NOT in the settlement path, nothing trusted or consolidated).** Build the **embedded finality-pinned follower** (reth engine + committer) whose overlay = reth's in-memory tree (Tiers A/B); the follower task advances the trie and rebuilds the overlay by re-execution on optimistic reorgs (**no custom durable rollback engine, no custom parent-hash detector, no `(height, block_hash)` archive** — all collapsed by M1/M3). It runs the **narrow MVP** (serve the body from held/overlay state + re-execute only the Sync block with per-tx instrumentation), the **no-op guard byte-for-byte** (`validation.rs:409-419`), and a **hard refusal** to attest without `sync_tx_statuses`. **The follower is an OBSERVER here: it does not consolidate, and nothing it produces is trusted or settled** — the live attestation stays stateless throughout, so this phase can run against the composer cursor and does **not** require M3 (M3 gates consolidation, Phase 4). On top of the follower, run the **standing shadow-check**: run **both** backends on **every settling window** — and note that in **driven mode every directive *is* a settling window** (`prover_dispatch` is one-in-flight, settling ⇔ `composition.is_some()`), so the shadow runs on **every** directive and "sampling" is moot there; reserve sampling only for a hypothetical non-driven mode. Assert identical `VerifiedWindow` including **length-parity** on `sync_per_tx_roots` and `sync_tx_statuses`, with **auto-flag (alarm) on any mismatch** (P3) — standing and continuous, not a one-time gate (it becomes auto-demote-to-stateless once the stateful path is ever trusted, Phase 4+). Note the mandated `sync_per_tx_roots` length-parity exercises the **interim-root** field G2 flags as **dormant under N=1** (`is_endpoint_root` always true, `main.rs:1349-1350`): since no production gate exercises that field under N=1, the shadow's **direct field comparison is its only coverage**.
  - **(G1 — complete the structural 'gates read copy A' wiring; the tx-scoped bind from Phase 1 now goes clean.)** With the follower's **full executed copy A** now in hand, complete the durable fix: route the cross-chain / #10 gates (`system_tx_flags_from_rlp`, `main.rs:1291`; `extract_inbounds`, `main.rs:2295`; outbound A3, `main.rs:2353`) onto the follower's **own full executed copy A** — **structural** (the gates physically cannot read copy B) and **future-proof for any body field**, superseding the Phase-1 tx-scoped interim (the `publicInputsHash`-bound DA payload / `hash_slow()` + `transactions_root` cheap-patch, which bind only the txs). This **structural copy-A routing must be in place before any stateful output is trusted / signed / settled (Phase 4)** — but note Phase 3 **intentionally** runs the stateful **observer** before this wiring is complete (nothing it produces is trusted or settled here). This is **escrow forgery, not liveness** (§8.G1) — on the same footing as the no-op guard and the hard-refuse-without-`sync_tx_statuses`, and **the one true soundness blocker of the whole design.**
  - **(G2 — scope the win honestly, don't oversell "kill witnesses".)** In driven mode **every** directive is a settling window (`prover_dispatch` is one-in-flight, settling ⇔ `composition.is_some()`) and `validate_window` **hard-bails without a witness per event** (`main.rs:666-668`). So witnesses stay **MANDATORY on the settling path forever** — the win is only the narrow **non-settling body**; while shadowing, steady-state compute is **strictly greater than today** (both backends run on every directive); and the shadow **can never retire** (two independently-versioned reth/revm builds, P3). Worse, the **interim-root** path — the only `VerifiedWindow` field with no header anchor — is **dormant under N=1** (every boundary is an endpoint, `is_endpoint_root` `main.rs:1349`), so "green on settling windows" is **vacuously green for the one field it most needs to protect.** Mitigation: state the win as "skip re-exec of the non-settling body," not "kill witnesses"; define a **sampling / backpressure policy** (bound the shadow's cost by **sampling**, not by retiring — while any stateful output is trusted the shadow can **never** fully retire, P3; retirement is permissible **only** in a pure-observer configuration where stateful attestation is never trusted); **flag interim-root parity as untestable under N=1**.
  - **(G3 — decide shadow sync vs async; must-decide.)** **Sync** shadowing ≈ **2× per-directive latency / ~half settlement throughput** while engaged (worst during backlog recovery). **Async** lets a bad root **attest before the compare** — turning the "hard precondition for trust" into a **post-hoc alarm**. Decide explicitly: **async-observer** (a detector, not a gate) **or sync only during a bounded bring-up window**.

- **Phase 4 — Consolidation + finality-driven persistence (medium-large; the FIRST TRUSTED stateful mode — requires M3 from Phase 2).** Now that the follower runs as a green observer (Phase 3), turn on **consolidation**: the follower consolidates its durable base to its **own** L1-finalized boundary (Tier C) — the durable trust root M3 makes independent — and from here a stateful attestation may be **trusted** for the first time, gated on the Phase-3 shadow being green (including the **no-op guard byte-for-byte** length-parity, `validation.rs:409-419`). Bound the **follower's own overlay** at a depth sized so `cap + finality_lag < memory-block-buffer-target (128)` (today the composer's cap is enabled at 1024 — far larger than the 128 buffer target — and, if naively reused, mis-gauged on `cursor`, `compose:88/129-130`). Boot the durable base from the prover's **own** reth persisted `safe`/`finalized` via `spawn_from_provider` (`block_committer.rs:190/216/227`); **boot-time reconciliation** of the attested-frontier pointer vs the reth finalized tip vs `DrivenCheckpoint` (not fsync-ordering); cold-boot re-derive by *executing* blocks (not `backfill_block`); a **hard genesis gate** (held `state(finalized)`/`state(settled)` must equal a stateless-verified anchor on a settling window before trust).
  - **(G5 — the boot gate + trie seed are composer-frame, not M3-independent.)** The hard genesis gate and the durable-base seed both validate via a **stateless (witness/composer-data) re-exec**, so they pin the held trie to the composer's view, not an independent re-derivation. And independent **frontier** data is structurally impossible (the frontier block has no L1-DA until the proof signs it — circular); even for settled history the cross-chain L1-DA reconstruction is unwired (`reconcile_batch_blocks` needs `system_tx_cfg`, the follower runs `None` and fails on any cross-chain Sync block, `deriver.rs:1140`). Accept that the prover's independence is **re-computation of state**, not an independent data source, and acknowledge the boot gate/trie seed as composer-frame (§12 G5).
  - **(G6 — the overlay-memory bound belongs to the FOLLOWER, not the composer's cap.)** The speculative-depth cap pauses block **building** in the **sequencer** (gauged on `cursor`, now enabled live at `EEZ_MAX_SPECULATIVE_DEPTH=1024` — far larger than the 128 buffer target). The prover follower **does not build blocks and cannot pause the chain**, so "the prover re-enables the cap" is **N/A**, and routing the attestation to stateless does **not** free the follower's in-memory tree. Re-gauging the *composer's* cap on `finalized_l2` would **stall composer production** whenever L1 finality lags (~64 blocks on Gnosis) — a **composer throughput change, not free wiring**. Mitigation: **bound the follower's overlay independently** (drop overlay → degrade to stateless past the cap), decoupled from the composer's building cap.
  - **(G7 — consolidation liveness is coupled to a settlement it cannot itself outrun.)** Consolidation advances only on L1 finality of settled batches, but settlement (single registered attester) is **downstream of THIS prover's own attestation** (`on_batch_posted` skips when `settled_count==0`, `deriver.rs:798-808`). During a settlement stall (the competition-wedge `StateRootMismatch`/OD-5 freezes) the durable base **freezes**, the composer keeps producing, the prover keeps attesting via stateless, and the **overlay grows** — consolidation **cannot outrun a freeze it must itself clear**. Mitigation: **bound the overlay + degrade**, and document that **consolidation pauses through any settlement stall** (it is an optimization, never a precondition).

- **Phase 5 — Hybrid routing + divergence handling (medium).** Only after live parity: the **own-frontier** selector (`select_backend(from, to, own_finalized, own_overlay_tip, overlay_cap, l1_healthy, bootstrapped)`); per-directive backend pinning; gap/catch-up handoff (case c); the L1-divergence table (cases a/b1/b2/d, §7) — **never gate attestation on own-L1**; degrade-to-stateless on `ReorgTooDeep`/lag-past-cap/persistent divergence. Enable hybrid only after Phases 1–4 prove parity live (the Phase-3 observer green + Phase-4 trusted consolidation); until then the daemon is pure-stateless, indistinguishable from today.

- **Phase 6 — Future zkVM `IProofSystem` + bound-settlement roadmap (large, multi-quarter; optional).** Per §10. Decide independently of Phases 0–5.
  - **(G8 — M3 is necessary but NOT sufficient for anti-replay; gates the deferred bound-settlement option.)** `_verifyProofSystemBatch` folds `getTimestampAndBlockHash(blockNumber).blockHash` **of the settlement chain** into `publicInputsHash`, and the prover **hard-refuses on mismatch** (`main.rs:831-836`). Under M3 the prover folds `blockhash(N)` from its **own** node; for **recent** `N` the own node and the settlement chain disagree by reorg-depth / propagation **honestly** → an honest prover signs a hash settlement can **never** match → **stall**. The only escape — **deep / finalized `N`** — **weakens freshness**. Mitigation: pin `N` to a **finality-stable depth on the settlement chain** and document the freshness trade.
  - **(G9 — a 2nd `IProofSystem` is an all-of-N cliff, no observe-only.)** On-chain verification loops **all** registered proof systems and reverts on **any** failure (`EEZ.sol:625-637`), so a 2nd PS is **mandatory the instant it is registered** — there is no observe-only slot. Off-chain, every single-PS prover **bails on `n_ps==2`** (`main.rs:828`). Mitigation: stage via a **threshold-of-N** or a **shadow registry**, and make `apply_proof` **per-PS-indexed**.

## 12. Risks, open questions, and what to validate first

**Validate first (in order):**
1. **STF bit-parity, continuously.** Stand up the Phase-3 shadow-check (the untrusted observer) on the live chain *before* any stateful attestation is trusted; alarm on any field-or-length mismatch. The make-or-break risk (P1/P3 — different reth/revm builds, builder-vs-validator header, `SparseState` vs full MPT).
2. **The independent-L1 premise (M3).** Stand up the prover's own `L1Watcher`/`Submitter`/`L1CanonicalHead` against a *separate* node and confirm it produces a `finalized_l2`/`cursor`/`settled_final_state` that match an independent re-execution — and that it **detects** a composer-cursor divergence (the (d) audit, `deriver.rs:197`) rather than trusting it.
3. **The `ReorgTooDeep` halt path.** Inject a >62 (b2) reorg on the prover's own L1 and confirm the watcher **halts** (after fixing `l1_watcher.rs:276-285`) and the prover **degrades to stateless + alarms** — not livelocks, not keeps signing on a frozen base.
4. **The fail-OPEN #10 path.** Prove the hard-refuse-without-`sync_tx_statuses` guard fires, and that the no-op guard (`validation.rs:409-419`) is reproduced exactly (length-parity test).
5. **Memory-window budget.** Confirm `cap + finality_lag < memory-block-buffer-target (128)` with the cap **re-sized down from the live 1024** and gauged on `finalized_l2`; inject an optimistic-bundle reorg and confirm it is rebuilt **in memory** with no DB unwind (the head-unbounded reth-Headers corruption must not recur).

**Top risks:**
- **STF bit-parity across two reth/revm builds** (P1/P3) — mitigated by the standing shadow-check + fail-closed self-rejection for *divergences*; the *relaxation* holes (S1/S2) need construction-level fixes.
- **Consolidation-trust-root soundness** — the new model's central soundness risk: M3 must land with or before M1, or consolidation is a regression (§8). Mitigated by sequencing Phase 2 (M3) before Phase 4 (consolidation).
- **Finality reversion (b2)** — the one residual durable-rollback case, and currently a silent livelock in the live code; mitigated by the real halt + stateless degrade, **not** by a custom rollback engine.
- **Crash-consistency across three durable artifacts** (reth finalized tip, follower locator, `DrivenCheckpoint`) — boot-time reconciliation, not an ordering primitive the committer doesn't expose.
- **Silent mis-anchor from a wrong `EEZ_INITIAL_STATE_ROOT`** — hard boot-time gate on a settling window.
- **Phase 3 is a full follower node, not a function call**, and **Phase 2 (own L1 node) is a real topology/ops dependency** (a separate L1 endpoint) — staffing/scope must reflect both.

**Residual gaps from the adversarial gap-hunt (G1–G9) — risks/decisions + mitigations:**
- **G1 (SOUNDNESS BLOCKER, Phase 1 tx-only bind / Phase 3 structural) — `event.block` is not preimage-bound under the stateful backend.** Gates read copy B (`main.rs:1291`/`2295`/`2353`), which the follower never re-hashes; a forged block forges outbound-A3 escrow (`EEZ.sol:1010`) with **no self-reject** (the outbound tx reverts in re-exec, `outbound_gate.rs:22-30`, so it never touches the state-root chain). **Mitigation — the clean fix is STRUCTURAL copy-A routing:** route the gates onto the follower's **full executed copy A**, so the gates physically cannot read copy B, it holds for **any** body field a future gate reads, and a pure-stateful deployment can drop copy B from the wire. The `publicInputsHash`-bound DA payload (tx lists + L2 entries only, `crates/eez-payload-codec/src/lib.rs:4`, built at `composer.rs:3178`) and the `hash_slow()` + `transactions_root` parity check are **tx-scoped binds** — a **complete** bind for today's tx-only gates but **not future-proof** (they bind only the txs, keep copy B on the wire — §8.G1). The **tx-only bind lands in Phase 1** (stateless-safe no-op, **before any stateful code**); the **full structural copy-A wiring lands in Phase 3** and **must be in place before any stateful output is trusted/signed/settled** (§8.G1).
- **S2 (fail-OPEN, Phase 1) — a missing `sync_tx_statuses` is fail-OPEN.** `system_txs_succeeded(None) → true` (`main.rs:914-917`) lets a backend attest a reverted-#10 batch the stateless path rejects. **Mitigation:** make a missing `sync_tx_statuses` a **hard refusal** where the settlement gates depend on it (`main.rs:1380`); stateless-safe (native-validate always emits statuses, `validation.rs:407/416`), so it ships in **Phase 1** before any stateful attestation.
- **G2 (HIGH ROI, Phase 3) — the standing shadow undercuts the premise.** Every driven directive is settling → witnesses stay mandatory there (`main.rs:666-668`); steady-state compute is strictly greater while shadowing; the shadow never retires (two builds, P3); interim-root parity is dormant under N=1 (`main.rs:1349`). **Mitigation:** scope the win to the non-settling body; sampling / backpressure policy (retire only in a pure-observer config where stateful is never trusted, else the shadow can never fully retire — P3); flag interim-root parity untestable under N=1.
- **G3 (MUST-DECIDE, Phase 3) — shadow sync vs async.** Sync ≈ 2× latency / ~half throughput; async lets a bad root attest before the compare. **Mitigation:** decide **async-observer (detector)** or **sync only during bounded bring-up**.
- **G4 (BLOCKER, Phase 2) — own-L1 health is undetectable.** The run loop swallows every `poll_cycle` error (`l1_watcher.rs:276-285`); a frozen own-L1 looks like honest lag, `l1_healthy` stays `true`, the prover consolidates on stale finality (finality polled ~12 s, `FINALIZED_REFRESH_TICKS`). **Mitigation:** finality-age / liveness probe drives `l1_healthy`; propagate errors as `Degraded`. Ships with M3.
- **G5 (refined, Phase 4) — frontier data-independence is structurally impossible.** The frontier block has no DA until the proof signs it (circular); only settled history has L1-DA, and the cross-chain L1-DA reconstruction is unwired anyway (`reconcile_batch_blocks` needs `system_tx_cfg`, follower runs `None`, fails on any cross-chain Sync block, `deriver.rs:1140`). **Accept/mitigate:** independence is **re-computation**, not an independent source; the boot gate + trie seed are composer-frame and must be acknowledged as such.
- **G6 (refined, Phase 4) — the memory bound belongs to the follower, not the composer's cap.** The composer's cap pauses *building* (gauged on `cursor`, enabled live at 1024 ≫ 128); the prover can't pause the chain and stateless routing doesn't free its in-memory tree; re-gauging the composer's cap on `finalized_l2` stalls composer production (~64-block Gnosis lag). **Mitigation:** bound the follower's overlay independently (drop → degrade).
- **G7 (refined, Phase 4) — consolidation can't outrun the settlement it must clear.** Settlement is downstream of this prover (`deriver.rs:798-808`); a settlement stall freezes the durable base while the overlay grows. **Mitigation:** bound overlay + degrade; document that consolidation pauses through any settlement stall.
- **G8 (roadmap, Phase 6) — M3 necessary, NOT sufficient for anti-replay.** Recent-`N` `blockhash` from the prover's own node honestly disagrees with the settlement chain → honest stall (`main.rs:831-836`). **Mitigation:** pin `N` to a finality-stable settlement-chain depth; document the freshness trade.
- **G9 (roadmap, Phase 6) — a 2nd `IProofSystem` is an all-of-N cliff.** On-chain reverts on any PS failure (`EEZ.sol:625-637`); off-chain bails on `n_ps==2` (`main.rs:828`); no observe-only. **Mitigation:** threshold-of-N or shadow registry; per-PS-indexed `apply_proof`.

**Open decisions for sign-off:**
1. **Prover's own L1 endpoint** — a genuinely separate node (M3 requires it; the composer's embedded loopback L1, `compose:50`, does NOT satisfy independence). Recommendation: a dedicated `EEZ_PROVER_L1_RPC_URL` to an independent chiado node.
2. **Speculative-depth cap value + gauge** — re-size (down from the live 1024), gauge on `finalized_l2`, size `< memory-block-buffer-target − finality_lag`.
3. **Authority on recovery** — recommend reth datadir's **finalized** tip authoritative for held state, `DrivenCheckpoint` for attested progress.
4. **Whether to ever stop populating `ControlEvent.witness`** — keep it on while any stateless backend (hybrid fallback or fleet peer) exists.
5. **Bound settlement / anti-replay activation** — M3's own L1 is the precondition; activating `blockNumber = N` (hard liveness coupling #1) buys anti-replay + per-batch unique hashes at the cost of prover-L1/settling-fork agreement. Decide with the zkVM track (§10).

**Net.** The **near-term HYBRID / OBSERVER path** runs both modes interchangeably behind the `validate_window → VerifiedWindow` seam with **no protocol, contract, composer, public-inputs, or wire change** — that structural claim holds (single consumer `main.rs:647`, single call site `main.rs:2071`, state-agnostic `publicInputsHash` `main.rs:846`, contract `ECDSAProofSystem.sol:30-31`/`EEZ.sol:634/1006`). (A **pure-stateful** deployment optionally **drops copy B + the witness from the wire** — which **is** a wire change, and the bandwidth / independence win — but §9 recommends hybrid-only, so present that drop as a structural point about what copy B is, not a delivered saving.) The new model **collapses** the old design's hardest pieces — the custom `(height, block_hash)` archive, the feed-native parent-hash detector, and the durable rollback engine — by pinning durable state to the prover's own L1-**finalized** boundary (M1) over reth's in-memory tree (M2), so the dominant optimistic reorg never reaches disk. It **adds** one hard prerequisite — the prover's own independent L1 follower (M3), without which consolidation is a soundness regression — and leaves **one** residual durable-rollback case: a finality reversion / too-deep L1 reorg, which the live `eez-l1` code currently mishandles and which the prover must turn into a halt-and-degrade-to-stateless. The own-L1 view is a **non-blocking, monotonic lower bound on durability + the L1-reorg/nonce oracle — never a gate on attestation**: healthy, it skips re-execution below the prover's own finalized base; lagging/halted/diverged, it transparently degrades to today's full stateless re-execution. The safe path is hybrid-only, own-finalized-frontier-routed, with the narrow Sync-block-only MVP, the construction-level S1/S2 fixes, M3-before-M1 sequencing, and a standing shadow-check as the hard precondition for trust.
