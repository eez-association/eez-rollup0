Inbound Witness Root Cause Analysis

Evidence report for the native validation failure observed on the edu/latest-plus-fixes deployment while testing inbound cross-chain calls. The core finding is that a block-level endpoint witness is insufficient for proving intermediate per-transaction state roots.

Branch: edu/latest-plus-fixes Port baseline: feat/crosschain-on-main Failure block: 44190 Date: 2026-07-08

Conclusion

Root cause established The witness proves the parent root to the final block root. The validator also needs roots after individual cross-chain transactions. Those intermediate trie transitions can require nodes that are not present in the final endpoint witness.
Failure trigger established In block 44190, transaction 2 deletes a persistent executions storage slot and transaction 3 recreates it. The final witness does not include the child node needed for the intermediate delete/collapse root.
Patch requirement We must keep per-crosschain state roots. The safe direction is an augmented witness that includes trie proofs for each required transaction boundary, while the prover still computes the roots.

What Was Ruled Out

Not a malformed captured witness Regenerating the block witness through reth produced the same class of result: enough for the endpoint root, insufficient for the intermediate root.
Not Legacy vs Canonical alone Legacy returned state=61 keys=35 codes=5 headers=1. Canonical returned state=60 keys=35 codes=4 headers=1. Neither included the 0x2728... node preimage.
Not missing key preimages The witness contains the account and storage key preimages that map to the affected path.
Not an EIP-1153 transient-root issue The failing trace is persistent SSTORE on the executions array path. Transient opcodes are present but are not the unresolved trie node.

Recommended Fix Direction

Keep per-crosschain roots as a prover-computed invariant. Do not trust composer-supplied roots and do not remove intermediate validation. The fix should make the witness large enough to prove every required transaction boundary.

Implementation Shape To Validate

  • Re-execute the block transaction by transaction on the parent state.
  • After each transaction that must have a proven root, merge cumulative transitions.
  • Build a trie witness for that cumulative HashedPostState against the same parent root.
  • Union and deduplicate trie nodes, codes, keys, and headers into one augmented ExecutionWitness.
  • Publish the augmented witness from the live node feed.
  • Update proverd durable backfill so it cannot fetch only the endpoint witness from debug_executionWitness.

First Proof Before Wiring

Build a one-off augmented witness for block 44190 and run the current native-validate binary unchanged. Passing this test would prove the witness-contract fix for the observed failure before changing the production flow.

Open Items
